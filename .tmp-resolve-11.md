## Resolution — service template & contribution surface

The template **embodies** the contract (ADR-0001). A new service is a folder in `services/<name>/` in this repo, copied from `template/` at the root.

**What a service looks like as code:** Python/FastAPI, own SQLite DB (SQLModel), own UI (FastHTML + Alpine.js, all JS/CSS **vendored locally — no CDN**, LAN/offline-safe), own API. `src/<name>/contract/` = vendored base + the 9 family modules (keep what `service.toml` declares, delete the rest). `capabilities/` = sub-services (audio: stt, tts, vad, cloning, realtime_chat) sharing the service's contract surfaces and one DB. `mcp_bridge.py` = universal agent surface, tools auto-generated from the OpenAPI spec, `@tool` overrides for English-friendly interfaces.

**Declaration:** `service.toml` (name/version/description, families, capabilities, UI nav, inference policy + privacy tier) · API self-declares via `/openapi.json` · models declared **per capability** in `models.toml` (description, source local-or-cloud, license, links: release/repo/license/evaluations, sizes, accuracy/speed ranks, modalities, max context, VRAM formula inputs incl. KV quant). `supported`/`recommended` are **computed** from hardware + model selection goal (`accuracy`/`size`/`speed`/`balanced`), never stored.

**Contract amendment (ADR-0001, base item 9):** **callable surfaces** — every service is driven by a human (UI), an agent (MCP), and deterministic workflows (OpenAPI). Family 3 narrows to tool-service semantics (resources/prompts, curated tools).

**Contribution surface (solo-first):** `template/` + copy-to-start ritual, short CONTRIBUTING.md checklist, `uv run check` + one minimal CI workflow on PRs touching `services/`. Community machinery deferred until demand. The per-domain repos (voice/images/llms/webscraper) are **out of scope**, ignored entirely.

**Assets:** `docs/adr/0002-service-template-and-contribution-surface.md` (amends ADR-0001) · CONTEXT.md terms: *capability*, *callable surfaces*, *model selection goal*.

**Ripples:** #20 registry gains tools for every service · #13 can call any service via MCP · #18 instantiates services from the template · #8 shares the UI kit · #4 sharpened (models.toml aggregation + resource story) · #19 expanded (cloud access machinery: connectors, credentials, billing, quotas).
