Knowledge · Document · Inference — Platform Architecture

wordslab-platform — three sibling services, one SQLite DB each, over the LAN. Grounding capability (ADR-0011), DocETL engine (ADR-0010), Document/Knowledge split (ADR-0009).

Document service — raw data

  • • Owns raw bundles + indexes (faithful representations)
  • • Capabilities: ingest/parse · organize · index · search/retrieval · raw extraction · split/embed
  • • Registers `chunks` data_source (`document.<bundle>`)
  • • Fetches the ontology from Knowledge for schema-constrained raw extraction

Knowledge service — reasoning & grounding

  • • Three capabilities: ontology (blueprint + validate) · entities (resolve) · graph (facts + provenance)
  • • Runs the DocETL engine (abstract request); executes resolve/grounding, does not own the machinery
  • • Review queue = shared HITL surface (human-or-agent); entity resolution scoped to one KB
  • • Registers `graph` data_source (`knowledge.<kb>`); IDs `entities.<ontology>.<kb>.<opaque>`

Interactions (the seams)

  • • Knowledge → Document: dispatch representation steps / fetch `chunks` where data lives
  • • Document → Knowledge: fetch the ontology (schema) for raw extraction
  • • Knowledge → Inference: LLM / classic-AI judgment as explicit implementation choice
  • • Document → Inference: embeddings (classic AI), aligned vector space
  • • Workflow / Agent → Knowledge: call( knowledge.docetl / .entities.resolve ); review queue
  • • Registry (core): name→URL resolver + `kind` tags; never in the request path
